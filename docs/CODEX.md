# Documentation and project context

Read the repository-root `CODEX.md` first.

## Documentation rules

- `bedlam-like-music-prd.md` describes approved and proposed product requirements.
- `project/tasks.md` is the task board; update status and evidence as work
  progresses.
- `project/decisions.md` records consequential Producer decisions and rejected
  alternatives.
- Checked-in behavior and commands must match the repository.
- Keep proposals clearly marked as proposed until the Producer approves them.
- Do not convert measurements into OKRs until the Producer approves the PRD and
  baseline data exists.

Architecture, API, security, development, deployment, and operations changes
must update their corresponding guide in the same work item.
